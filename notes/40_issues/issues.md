## 1. 出力の安全性 ✅ **済** 3 件（済 3）

レポートは HTML で残り、そのまま人に見せる前提で作っている。**ローカル PC 固有の情報が出力に残らないことを、生成のたびに確かめられる状態にする**のがこのグループの目的である。

<details>
<summary>i260908-01 伏せ字がフォルダ名の途中で切れる ✅ <strong>済</strong></summary>

### 状況

3 章「プロセス一覧」のコマンドラインに、伏せ字が途中までしか掛かっていない箇所が残っていた。**ユーザー名で始まるフォルダ名に対して、ユーザー名の部分だけが置き換えられ、後ろに続く文字がそのまま出ていた。**

件数は起動しているプロセスの数で変わる。2026-09-08 06:00 の記録で 16 件、同 12:00 の記録で 28 件。

### 原因

2 つが重なっていた。

1. **実体パスがドライブ表記へ戻っていなかった。**`-SubstDrive` / `-SubstRoot` は UAC で昇格し直すときの引数としてしか渡らない。`nopause`（`-NoElevate`）で起動する経路 — タスクスケジューラと管理者コンソール — では空のままで、実体パスが出力に残っていた
2. <strong>伏せ字が単純な部分文字列の置換だった。</strong>残った実体パスにユーザー名の置換が掛かり、フォルダ名の先頭だけが伏せられて残りが見えた。ユーザープロファイルのパスの置換にも同じ穴があり、プロファイル名で始まる別のフォルダで残骸が出ていた

検証の側も見落としていた。**「ユーザー名が 0 件」を数えていたため、置換後に残った断片は検出できなかった。**

### やること

| # | やること | 状態 |
|---:|---|---|
| 1 | subst の割り当てを実体パスの側から引き当て、引数が渡らない経路でもドライブ表記に戻す | ✅ **済** |
| 2 | ユーザー名の置換を、区切りに挟まれた要素ごと伏せる形にする | ✅ **済** |
| 3 | ユーザープロファイルのパスの置換に、後ろが区切りであることの条件を足す | ✅ **済** |
| 4 | 検証を「伏せ字の直後が区切り文字以外なら異常」で数える形に変える | ✅ **済** |
| 5 | コンピューター名の置換も同じ形に直す | ✅ **済** |
| 6 | マスキングの回帰テストを `tests/` に置く | ✅ **済** |

### 直した内容

`tools/80_ops/inspect-process-memory.ps1` に 3 か所。

```powershell
# subst の割り当てを実体パスの側から引き当てる（新設）
function Find-SubstRoot([string]$Path) { ... }
if (-not $SubstRoot) { Find-SubstRoot $PSScriptRoot }

# Hide-Private: 引数が渡っていなければ引き当てた値を使う
if (-not $substRootUsed) {
	$substRootUsed = $script:FoundSubstRoot
	$substDriveUsed = $script:FoundSubstDrive
}

# Hide-Private: 後ろが区切りでないときは置換しない
$r = $r -replace ([regex]::Escape($script:UserProfile) + '(?![^\\/:"'' ])'), '~'

# Hide-Private: 区切りに挟まれた要素ごと伏せる
$r = $r -replace ('(?<![^\\/:"'' ])[^\\/:"'' ]*' + [regex]::Escape($script:UserName) + '[^\\/:"'' ]*'), '<username>'
```

コンピューター名の置換も同じ形にした。同じ欠陥を持つが、実際に当たった記録はまだ無い。

### テスト

`tests/test-hide-private.ps1` に 16 件。<strong>実装本体から伏せ字の定義だけを切り出して評価するので、スクリプトを直すとテストがそのまま新しい実装を見る。</strong>実行は `tools/40_test/run-tests.ps1`（同名の cmd あり）。

実在の名前は使わず、`user1` ・ `HOST1` ・ 合成したフォルダ名を差し込んでいる。区切りの判定を確かめるため、<strong>「ユーザー名が 0 件」ではなく「伏せ字の直後が区切り文字以外なら異常」で数える検証を横断で入れた。</strong>全件通っている。

> [!NOTE]
> <strong>検証の作り方を変えた。</strong>置換後の文字列に名前が残っていないことだけを見ると、置換によって生まれた断片は見えない。**伏せ字の直後を見るのが、この欠陥に対する唯一の検出手段だった。**

<summary>i260908-02 既存のレポートに残った伏せ字漏れの扱い ✅ <strong>済</strong></summary>

### 状況

[i260908-01](#1-出力の安全性-済-3-件済-3) を直す前に生成した HTML が `logs/` に **20 ファイル**あり、全ファイルが伏せ字の残骸を含んでいた。**合計 328 件**（実体パスの形 288 件・それ以外 40 件）。1 ファイルあたり 2 件から 39 件で、起動しているプロセスの数によって変わる。

> [!IMPORTANT]
> <strong>最初に数えたときは 14 ファイルだった。</strong>検索式を `*-mem-*-log.html` と書いたため、`-mem-log.html`（区分の入らない初期の 6 ファイル）が漏れていた。<strong>0 件ではなく少ない件数が返るので、結果を見ても欠けに気づけない。</strong>件数は必ず数え直す。

### 選んだ扱い

| 案 | やること | 結果 |
|---|---|---|
| A | <strong>採用。</strong>残骸のある箇所だけを書き換える | 記録は残り、時系列の比較も続けられる。書き換えた印をフッターに残した |
| B | 消して、次の記録から積み直す | 確実だが、09-05 から積んだ比較の系列が切れる |
| C | そのまま置き、外へ出さない運用にする | 手間はないが、うっかり配布する余地が残る |

### やったこと

| # | やること | 状態 |
|---:|---|---|
| 1 | 扱いを決める（A / B / C） | ✅ **済** |
| 2 | 決めた扱いを 20 ファイルに適用する | ✅ **済** |
| 3 | 全ファイルを数え直し、残骸 0 件を確かめる | ✅ **済** |
| 4 | 書き換えたことを本文にも残す（伏せ字に触れている 3 ファイルの結論と所見） | ✅ **済** |

### 書き換えの手順

`tools/80_ops/sanitize-report-logs.ps1`（同名の cmd あり）で行った。<strong>伏せる対象の値をスクリプトにリテラルで書かず、すべて環境変数から取る。</strong>既定は数えるだけで、書き換えるときは `-Apply` を付ける。

1. subst の割り当てを実体パスの側から引き当て、直す前の伏せ字が実体パスに対して作った形を組み立てる
2. その形をドライブ表記へ置き換える（288 件）
3. 残った伏せ字の直後の文字を落とし、区切りまで伏せた形にする（40 件）
4. フッターに書き換えた印を足す。二重には足さない
5. `convert-encoding --to html` で BOM と改行を揃える

書き換え後、20 ファイルすべてで **残骸 0 件・ユーザー名 0 件・実体パス 0 件**、BOM 付き UTF-8・LF・`section` の対応も保たれていることを確かめた。

> [!NOTE]
> <strong>数値には触っていない。</strong>書き換えたのはコマンドラインの伏せ字だけで、メモリの値・件数・所見は採取時のままである。

## 2. 自動化 ⚠ **着手** 1 件（着手 1）

タスクスケジューラの実行に、人手を介さない後続処理を持たせる話を集める。**無人で動く分、途中で止まっても気づきにくいことを前提に確かめる**のがこのグループの目的である。

<summary>i260913-01 考察の自動追記（`claude -p`）が長らく無効なまま ⚠ <strong>着手</strong></summary>

### 状況

`tools/80_ops/inspect-process-memory.cmd` は、レポート生成後に `claude -p` で考察を追記する作りになっているが、**登録されているタスクの引数が `nopause noai` であるため、この追記は一度も動いたことがない。** ここまでの `ch06「結論と所見」` は、すべてこのセッションで手作業により追記したものである。

### 検証したこと

| 論点 | 結果 |
|---|---|
| 権限確認で止まらないか | **止まらない。**`~/.claude/settings.json` の `permissions.defaultMode` が `auto` になっており、`--dangerously-skip-permissions` を付けなくても Edit ができることを、使い捨てファイルで確認した |
| `logs/last-report.txt` の解決 | 正しく最新レポートを指していることを確認した |
| Task Scheduler（S4U）から起動したときに `claude` が見つかるか | **未確認** 。`claude` はユーザー PATH で解決しており、システム PATH には無い。S4U はユーザープロファイルを読み込む方式なので理屈のうえでは通るはずだが、実機のタスクから動かして確かめてはいない |
| 手動実行で「ハングする」という報告の原因 | <strong>ハングではなかった。</strong>実際の cmd と同じコマンドを 1 MB のレポートに対して実行したところ、<strong>5 分 36 秒かかり、その間は画面に一切出力が無かった。</strong>権限確認で止まっていたのではなく（`--dangerously-skip-permissions` 無しでも完了した）、進捗が見えないまま長く待たされる形になっていた。利用者は 3 分ほどで「止まった」と判断し、途中で消していた |

### 見つかった課題

> [!IMPORTANT]
> <strong>ch06「結論と所見」の作り方が、どこにも書かれていない。</strong>比較の手順（`reports-admin.txt` の 1 つ前の行と比べる）・章の構成（いまの状態／前回との比較／区分ごとの内訳／気になった点／次に見るとよいところ）は、いずれもこのセッションの指示文の中にしか存在しない。`claude -p "%REPORT% に考察を追加して"` という薄い指示のまま `noai` を外すと、回ごとに書き方がぶれる。

あわせて、レポート本体が 600〜700 KB あるため、1 日 4 回この読み込みが発生する分のコスト増も考慮点になる。
