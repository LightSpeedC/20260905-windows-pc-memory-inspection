この計画について

目的

inspect-process-memory.cmd が呼ぶ claude -p の考察（ch06）について、次の4点を可能にする。

  • モデル・思考の深さ（effort）を、実行のたびに指定できる
  • 指定したモデル・effort を、実行時の画面に表示する
  • 「何に着目して調べるか」を外部ファイルに持たせ、コードを直さずに増減できるようにする
  • 最新のレポートを見つけて開くだけの、root 用の別 cmd を用意する

きっかけ

課題 i260913-01 の「やること」に、ch06 の作り方が資料として書かれていないという指摘が残っている。今回の「着目点を外部ファイルに置く」は、この指摘への対応も兼ねる。あわせて、手動実行時に検討モデルを一時的に変えたい（既定は変えず、引数で上書きしたい）という要望が出た。

この計画でやらないこと

  • 登録済みタスクが実際に渡す引数（nopause noai）は変えない。root の cmd を経由する形に変えるが、既定で渡る引数の中身は今までと同じにする
  • noai を外す判断はしない。i260913-01 の「やること」5〜6番として残す
  • 着目点ファイルの中身（実際にどの観点を入れるか）を、この計画で確定させない。枠組みだけを作り、中身は運用しながら増減する前提にする
  • 最新レポートを開く cmd を、タスクスケジューラへ新規登録しない。cmd 本体を用意するところまでとし、登録は別途の指示を待つ

既存の引数の作り

inspect-process-memory.cmd は nopause ・ noai という**裸の語**を引数に取る作りで、key=value 形式の引数はまだ無い。今回 model: ・ effort: を初めて足す。

作るもの

1. 引数 model: ・ effort:

引数省略時渡し方
model:<名前>--model を付けない（アカウント既定のまま）claude --model <名前> --effort <値> -p "..."
effort:<値>--effort を付けない（既定のまま）同上

使い方の例: inspect-process-memory.cmd nopause model:sonnet effort:high

実装中に見つかった、計画との差分。当初は model=sonnet（= 区切り）で設計したが、実際に試したところ model と sonnet に割れて渡り、値が空のまま既定扱いになった。cmd は =（と , ;）を、引用符が無い限りスペースと同じ引数区切りとして扱う。引用符で囲めば回避できるが、手打ちで毎回引用符を付けるのは現実的でないため、区切りを : に変更した。コロンなら引用符無しで正しく1つの引数として渡ることを実測で確認済み。

2. 実行時の表示

claude -p を呼ぶ直前に、選んだ内容を1行で表示する。あわせて、観点ファイルの中身もそのまま画面に出す。その回の考察が何を踏まえて書かれるのかを、実行した本人がその場で確認できるようにする。

type は使わない。観点ファイルは Markdown の慣例どおり BOM 無し UTF-8 で作る予定だが、type はコンソールの既定コードページ（日本語 Windows では SJIS）でバイト列を解釈するため、UTF-8 の日本語は文字化けする。

今回採用するのは node 版。

echo モデル: sonnet（指定） / effort: high（指定）
echo モデル: 既定 / effort: 既定　（どちらも省略した場合）
echo ---- 観点ファイルの内容 ----
node -p "fs.readFileSync('inspect-process-memory-observations.md').toString()"
echo -----------------------------

node -p（-e・REPL も同様）では fs が require 無しでそのまま使える。readFileSync(...).toString() は既定で UTF-8 として文字列化するため、'utf8' を明示しなくてよい。バイト単位で正しい UTF-8 が出ることは実測で確認済み。この時点でカレントは既にプロジェクト直下（上の方で cd /d 済み）のため、観点ファイルは相対パスでそのまま参照できる。

コードページの実測値は、この検証環境（このセッションが動いている PC）のもの。実行前からコードページ 65001（UTF-8）で、chcp を挟まなくても node -p は正しく表示された。ただし実際に運用するPCは別の機体で、コードページが CP932 である可能性がある。共通ルール「検証環境の状態を過信しない」のとおり、この結果を運用機にそのまま当てはめない。実機での確認は利用者が別途行う。

参考: PowerShell 版

コンソールの出力コードページを自分で UTF-8 に切り替えたうえで読む形。実測で確認済み（[Console]::OutputEncoding を UTF-8 にしたうえで [System.IO.File]::ReadAllText() で読むと正しく表示される）。Get-Content 単体は共通ルール「PowerShellの落とし穴」のとおり BOM 無し UTF-8 を CP932 として読んでしまうため使わない。

powershell -NoProfile -Command "[Console]::OutputEncoding=[System.Text.Encoding]::UTF8; [System.IO.File]::ReadAllText('inspect-process-memory-observations.md')"

今回は採用しないが、node が使えない環境に持って行くときの代替として残す。

4. root の起動用 cmd（タスクの再登録が要らないようにする）

プロジェクト直下に、タスクスケジューラが直接指す司令塔役の cmd を1本置く（run-inspect-process-memory.cmd）。中身は tools/80_ops/inspect-process-memory.cmd を呼ぶだけで、渡す引数（nopause ・ noai ・ 今後の model: 等）は変数として1行にまとめる。

@echo off
rem タスクスケジューラはこのファイルを指す。
rem 実行内容を変えたいときは、この DEFAULT_ARGS の1行だけを直せばよい。
rem タスクの再登録は不要（Command が指す先はこのファイルのまま変わらないため）。
set "DEFAULT_ARGS=nopause noai"
call "%~dp0tools\80_ops\inspect-process-memory.cmd" %DEFAULT_ARGS% %*

手動での個別テストは、この root の cmd を経由せず、tools/80_ops/inspect-process-memory.cmd を直接、好きな引数で呼ぶ。root の cmd は「タスクスケジューラが何を実行するか」だけの置き場にする。

5. タスクの再登録（Command の向き先を変える）

登録済みタスクの Command を、今の tools/80_ops/inspect-process-memory.cmd（実体パス）から、新しい root の run-inspect-process-memory.cmd（実体パス）へ変更する。トリガー（6時間ごと）・実行アカウント（S4U）・その他の設定は変えない。Set-ScheduledTask -Action で action だけを差し替える形にする。

etc/ の控え・tools/ の雛形が古くなる。課題 i260908-03 で作った etc/ai-pc-inspect-process-memory.xml（実値の控え）と tools/80_ops/ai-pc-inspect-process-memory.xml（雛形）は、いまの Command（tools/80_ops/inspect-process-memory.cmd を直接指す）を記録したものである。Command を変えたら、この2つも新しい内容（root の cmd を指す形）へ更新しないと、実際の登録内容とずれる。

6. ch06 の作り方を資料にする（i260913-01 の課題への対応）

3番の観点ファイルが、そのまま「ch06 の作り方を資料として書く」（i260913-01 のやること 3番）を満たす形にする。これまでこのセッションで積み重ねてきた形式（いまの状態／前回との比較／区分ごとの内訳／気になった点／次に見るとよいところ、章数に応じた色相の振り直し等）を書き写す。

決めておくこととリスク

決めること

論点案理由
引数の形model:sonnet（key:value、コロン区切り）既存の裸引数（nopause）と見分けが付く。= は cmd が既定でスペースと同じ引数区切りとして扱うため、引用符無しで model=sonnet と書くと model と sonnet に割れる。実装時に実際に踏み、コロンに変えて解決した（下記コラム参照）
観点ファイルの形式Markdown・箇条書き人が直接編集する前提のため、HTML の見た目の作法（色相・目次等）は不要。プレーンな一覧で十分
観点ファイルの中身この計画では確定させない運用しながら増減する前提のため。初版は「気づいたものを書いておく」程度に留める
root cmd の名前run-inspect-process-memory.cmdroot にはこれから増えうる他のツールの起動用 cmd も並ぶ可能性があるため、対象が分かる名前にする
タスクの差し替え方Set-ScheduledTask -Action で action だけ差し替えるトリガー・実行アカウント（S4U）等、他の設定に触れずに済む

リスク

リスク起きること備え
存在しないモデル名・effort 値を渡すclaude がエラーで終了する手動実行のみが対象のため、実行者が画面のエラーで気づける。自動化はしない
観点ファイルが肥大化する読み込みに時間がかかる／考察が散漫になるこの計画の範囲外。運用しながら見直す
cmd の引数解析ミスmodel: ・ effort: の値が正しく渡らない手順8で3パターンを目視確認する
タスクの差し替えを誤る次の定期実行が動かなくなる（取り返しがつきにくい。気づくのが最大6時間後になる）手順9の直後に Get-ScheduledTask で内容を確認し、手順11で実際の実行結果まで確かめる。うまくいかなければ Command を元（tools/80_ops/inspect-process-memory.cmd）へ戻す
etc/・雛形の更新漏れ控えが実際の登録内容と食い違ったまま残る手順10で明示的に更新する
手順9（タスクの Command 差し替え）は、このプロジェクトで初めて登録済みタスクの中身に触れる操作である。これまでの計画（p260908-01）では「タスクの再登録はしない」を明言していたが、今回は利用者の指示により、その制約を外して実施する。

完了の条件

  • model: ・ effort: を指定した実行と、指定しない実行の両方で意図どおり動く
  • 観点ファイルが root に存在し、claude -p の指示文がそこへのポインタになっている
  • root の run-inspect-process-memory.cmd が存在し、登録済みタスクの Command がそれを指している
  • 次の定期実行が、新しい Command のとおりに動いたことを確認済み
  • etc/・雛形が新しい Command の内容と一致している
  • 課題 i260913-01 のやること 3番が済になる
  • claude -p を呼ぶ直前に、観点ファイルの中身が画面に表示される

最新レポートを開く cmd

目的

「今どうなっているか」を見るのに、logs/ の中を辿らなくて済むようにする。最新の日付のレポートを見つけて開くだけの、単純な cmd を root に用意する。手動で使うほか、ログオン中だけ動くタスク（S4U ではない、通常のログオン時実行）として登録する使い方も想定する。

作るもの

項目内容
置き場プロジェクト直下 open-latest-report.cmd
やることlogs/ 配下を再帰的に探し、名前が最も新しい（＝日付が最新の）*-mem*-log.html を既定のブラウザで開く。それだけ
昇格・substどちらも不要。%~dp0 からの相対探索のみで、実体パス・ドライブ表記のどちらで置かれていても動く
 
@echo off
setlocal enabledelayedexpansion
set "LATEST="
for /f "delims=" %%f in ('dir /b /s /a-d "%~dp0logs\*-mem*-log.html" 2^>nul ^| sort /r') do (
	if not defined LATEST set "LATEST=%%f"
)
if not defined LATEST (
	echo レポートが見つかりませんでした。
	pause
	exit /b 1
)
start "" "%LATEST%"
検索式は *-mem*-log.html にする（*-mem-*-log.html ではない）。課題 i260908-02 で踏んだのと同じ落とし穴で、区分の付かない初期のファイル名（...-mem-log.html）を *-mem-*-log.html は拾えない。今回は「最新の1件」を探すだけなので実害は無いが、書き方は揃えておく。
