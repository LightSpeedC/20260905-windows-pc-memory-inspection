この計画について

目的

タスクスケジューラの登録定義から、ローカル PC 固有の値を外す。リポジトリに入るものからは実値を消し、登録をやり直す手段は残す。

きっかけ

個人情報の点検で、この 1 ファイルだけが残っていた。logs/ の生成物（20 ファイル）は課題 i260908-01 ・ i260908-02 で片付いたが、登録定義は点検の対象に入っていなかった。

UTF-16 のファイルは Grep から漏れる。0 件ではなく一部だけが返るため、結果を見ても欠けに気づけない。この 1 件は text find で探して初めて見つかった。点検の道具を変えなければ、いつまでも見つからなかった。

この計画でやらないこと

  • タスクの再登録。既に登録済みで動いているものは触らない。XML は記録と再現の手段として扱う
  • タスクの内容の変更。実行時刻（6 時間ごと）・引数（nopause noai）・実行条件は変えない。noai を外す件は別に扱う
  • セッションログの扱い。etc/ のログ（JSONL）はフックが自動コピーしたもので、共通ルールで Git 管理外。今回の対象外
  • ほかの登録定義の作成。ログ圧縮のタスク（archive-old-logs）は p260905-01 の段取りに残す

作るもの

2 つを両立させる。実値のコピーは Git 管理外へ置き、リポジトリ側は他の人が再現できる雛形にする。

#置き場役目文字コード / 改行Git
1etc/ai-pc-inspect-process-memory.xmlいまのファイルをそのままコピー。登録をやり直したいときに schtasks へそのまま渡せるUTF-16LE ＋ BOM ＋ CRLF（現状のまま）除外
2tools/80_ops/ai-pc-inspect-process-memory.xml雛形。固有の値をプレースホルダにする。schtasks へ直接は渡さないUTF-8 ＋ LF管理
3tools/80_ops/fill-task-xml-template.ps1（＋同名の cmd）雛形を実値で埋める。今回は雛形の検証用で、実際の登録はしないBOM 付き UTF-8 ＋ CRLF管理
実装時に名前の衝突が見つかった。tools/80_ops/register-inspect-task.ps1 は既に存在し（2026-09-06 作成）、Register-ScheduledTask コマンドレットで直接登録する別の仕組みだった。ai-pc-inspect-process-memory.xml を読み書きするスクリプトは他に無く、この XML は登録済みタスクの控え（スナップショット）として単体で存在していたと分かった。既存の登録スクリプトは変更せず、新しいスクリプトは別名にすることをユーザーに確認して決めた。登録手段は当面 2 つ並存する（既存はコマンドレット方式、今回追加分は XML の雛形を埋めるところまでで登録は行わない）。

置き換えるプレースホルダ

プレースホルダ元の箇所登録時に埋める値の取り方
{USER_SID}<UserId>whoami /user の出力から取る
{PROJECT_ROOT}<Command>subst の割り当てを実体パスの側から引き当てる（Find-SubstRoot と同じ考え方）
{USER_ACCOUNT}<Author>$env:USERDOMAIN ＋ $env:USERNAME
{HOSTNAME}<URI> 等にホスト名が入っていれば$env:COMPUTERNAME
雛形は UTF-8 でよい。schtasks が読むのは登録スクリプトが tmp/ に生成したほうで、雛形そのものは渡さない。.editorconfig の既定（charset = utf-8）に合わせられる。

登録スクリプトの動き

  1. 雛形を読み、プレースホルダを実値で埋める
  2. 埋め残しが無いことを確かめる（{ で始まる語が残っていたら止める）
  3. tmp/ に書き、convert-encoding --to reg で UTF-16LE ＋ BOM ＋ CRLF にする
  4. schtasks /create /xml で登録する
  5. tmp/ の一時ファイルを消す（実値を含むため、残すかどうかは判断しない）

手順

#やること確かめること
1etc/ へコピーする（実値のまま・文字コードを変えない）大きさとハッシュが元と一致する
2tools/ 側を convert-encoding --to utf8 で UTF-8 にする中身が読める（text read）
3Edit でプレースホルダに置き換えるtext find で固有の値が 0 件
4convert-encoding --to utf8/lf で改行を揃えるUTF-8 ＋ LF
5登録スクリプトと cmd ランチャーを作る構文エラーなし（Parser::ParseFile）
6雛形を埋めた結果を etc/ のコピーと比べるプレースホルダ以外が一致する
7テストを全件実行する失敗 0 件

順序の理由

先に etc/ へコピーしてから tools/ 側を書き換える。途中で中断しても実値が失われないようにするため（共通ルール「ファイルの移動・分割・置き換え時の順序」）。

登録の確認は別に行う

手順 6 は「埋めた結果が一致するか」までで、実際の登録は行わない。タスクは既に動いているため、登録をやり直す必要が出たときに、そのとき指示を受けて実行する。

実施済み。7 手順すべて完了した。手順 6 の比較は差分 0 行（雛形を埋めた結果が etc/ のコピーと一致）、手順 7 のテストは全件成功（16 件）。etc/ を除く全フォルダで固有の値が 0 件であることも確認した。実装中に見つかった計画との差分（登録スクリプトの名前衝突・プレースホルダの追加）は課題 i260908-03 に記録した。

決めておくこととリスク

決めたこと

論点決め理由
SID かアカウント名かXML に {USER_SID} を置き、登録時に埋めるLogonType S4U を XML で指定する形を保つため。/RU で渡す形にすると XML の指定と二重になる

リスク

リスク起きること備え
UTF-16 を Edit で直すエラーが出ず、成功が返り、中身が壊れる先に UTF-8 化する（手順 2）。etc/ のコピーが残っているので戻せる
プレースホルダの埋め残し登録が失敗するか、間違った値で登録される登録スクリプトで { の残りを検出して止める
tmp/ の消し忘れ実値を含む一時ファイルが残る登録の直後に消す。Remove-Item は単独のコマンドで実行する
点検の漏れまた別の文字コードのファイルが残る点検は text find で行う。Grep で数えない
この計画を実施しても、etc/ には実値が残る。共通ルールで etc/ は Git 管理外だが、フォルダごと誰かに渡せば実値も渡る。etc/ を配布物に含めない運用が前提になる。
