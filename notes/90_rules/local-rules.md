# ローカルルール

📅 作成: 2026-09-21 / 更新: 2026-10-07

## 1. 結論と所見（ch06）の視覚化

共通ルールの「HTMLデザインルール」を、このプロジェクトのレポート（`logs/` 配下の `*-mem-admin-log.html`）の ch06「結論と所見」に限って上書きする。理由は、ch06 は数値の 大小比較が主目的で、共通ルールが想定する読み物用の図（SVG図・callout 等）だけでは 表内の値の大小が伝わらないと利用者から指摘を受けたため。

### 差分: 表の中に虹色バーを埋め込む

共通ルールは図を「表と別枠」で置く想定だが、ch06 では複数行の値を比較する表（区分ごとの内訳、 2GB以上の区分の内訳など）は、**表のセル内に直接** SVG バーを埋め込む。値が多いものほど赤、 少ないものほど紫に近づく虹色（`hsl(280*(1-値/最大値),78%,25%)` → `hsl(...,58%,55%)` の2色グラデーション、幅は `値/最大値 * 150px`）。

### 差分: 状態バッジを行ごとに付ける

コマンドライン系の表（node/bun/PlayWright・claude・PlayWright/Chromium）は、行ごとに `badge b-ok`（☑ OK・緑）または `badge b-ng`（× 要調査・赤）を先頭列に付ける。 残留・新規出現・未確認のものは `b-ng` にする。共通ルールのバッジは種類のラベルとして 使う想定だが、ch06 では「注意して見るべきものはどれか」を一目で分かるようにする目的で使う。

### 差分: 前回との比較の図は、グレイのグラデーションで余白を見せ、pagefileは別の行にする

「前回との比較」の図は、ch01 の最初の図（物理メモリの使用状況）と同じ配色にする （使用中=赤、空き=緑）。軸は物理メモリ総量までとし、それより先には伸ばさない。 WS合計・コミット合計も同じ px/MB の目盛りに揃えて赤バーで描き、値を描いた残りは **薄いグレイのグラデーション**で塗って余白を見せる。 ページファイル（pagefile）は別の行として、同じ目盛りで確保サイズと空きを赤・緑で描く。 サイズ・使用量は `Get-CimInstance Win32_PageFileUsage` の `AllocatedBaseSize`・`CurrentUsage`（MB）から取得する。これは現在の値であり レポート取得時点の値ではないため、図中にその旨を注記する。 **WS合計・コミット合計が物理メモリ総量を超える場合は、軸の右端で止めず超えた分だけ バーを右へ伸ばし、超過分を本体より濃い色にして超えたことが分かるようにする** （図の横幅もその分広げる）。

### 差分: 実際のコマンドライン文字列を表に書く

共通ルールはコマンド見本の書き方（ダブルクォートで囲む等）だけを定めるが、ch06 では プロセスの素性を確かめる目的で、要約した説明文だけでなく**実際のコマンドライン文字列**を 列として持つ。デスクトップ版 `claude.exe` のような長大なコマンドラインは、 役割が分かる先頭部分（`--type=renderer --user-data-dir=…` 等）だけを書く。

### 差分: 2GB以上の区分は、プロセス別の内訳表を別に作る

「区分ごとの内訳」で2GB以上になった区分（Windows本体・ブラウザ・開発ツール等）は、 実行ファイル別に分けた表を別に作る。区分の合計だけでは中身が分からないため。 件数の多い小さいプロセスは「上記以外・小さいもの多数」のように1行にまとめてよい。

> [!NOTE]
> **この節の詳しい章立て・観点は `inspect-process-memory-observations.md` に書く。** ここ（ローカルルール）は共通ルールとの差分だけを持ち、ch06 を書くときの具体的な手順・章立ては そちらを見る。

## 2. レポート生成のチェック

タスクスケジューラは6時間ごと（0:00・6:00・12:00・18:00）にレポートを生成する （「gitブランチ」等と同じ共通ルールの対象外、この項はこのプロジェクトだけの決めごと）。

### チェックのタイミング

各実行から15分後（0:15・6:15・12:15・18:15）に、直近のレポート HTML （`logs/reports-admin.txt` の最終行）が生成されているか、ch06「結論と所見」まで 正しく追記されているかを確認する。cron 式は `15 0,6,12,18 * * *`。

### セッションの開始時

cron とは別に、**セッションを開いたら、`logs/check-report.log`（レポート）と `logs/check-pc-memory-collector.log`（収集）の最後の行を見る**。❌ 異常が出ていれば、報告する。cron は、セッションを閉じている間は動かないため、その間に起きた異常を、ここで拾う。

> [!NOTE]
> **cron はセッションの中だけで生きる（共通ルール参照）。** このセッションを閉じると消え、7日で自動失効する。継続するかは利用者が都度決める。

## 3. サービスの exe の置き替え

考え方（実行中の exe は、名前を変えて退避してから置く。切り替えはサービスの再起動。管理者なしの再起動は、依頼のファイルで受ける）は、共通ルール「常駐サービスの置き場と、exe の置き替え（Windows）」に従う。**ここには、このプロジェクトの具体的なコマンドと値だけ**を書く。

1. **`tools\20_build\build-pc-memory-collector.cmd -Restart`** で、ビルド → 退避して置き替え → 再起動の依頼までを行う（管理者は要らない）。退避先は `tmp/`、受信箱は `_data/request/inbox`。
2. 結果は、`_data/request/comp/`（完了。新しい版が書かれる）か `error/`（失敗。理由が書かれる）に出る。再起動の間（約 10 秒）は、収集が止まる。毎分の区切りの直後に行うと、行が欠けない。
3. ビルドせずに再起動だけ頼むときは、`tools\80_ops\request-restart.cmd`。
4. **受信箱を持たない古い版**が動いているときだけ、管理者で `deploy\rust-ai-pc-memory-collector-winsw.exe restart` する。
5. **いまのプロセスの状態を調べたいとき**（メモリが急に増えた等）は、`tools\80_ops\request-inspect.cmd top:20`。管理者は要らず、再起動もしない。コミットの大きい上位と、システム全体の値が表示される。結果は `_data/request/comp/` にも残る（コマンドラインは入らない）。

`install-pc-memory-collector-service.cmd` は、定義や winsw を変えたときの**登録の作り直し用**。exe だけを替えるときは使わない（毎回、停止・削除・再登録が走り、管理者の操作が増える）。

## 4. DB とバックアップに、資格情報が入りうる

共通ルール「機密情報のマスキング」（クレデンシャルを、ファイルにも書かない）からの**例外**。

- **何が例外か**: プロセスのコマンドラインを、**そのまま** DB に記録する。引数にトークン・パスワード・API キーが入るプロセス（`--token`・`--password`・`Authorization:` 等）が、実際にある。ユーザープロファイルのパスだけは、`~` に置換する。
- **対象のファイル**: `_data/pc-memory.db`（と `-wal`・`-shm`）・`_backup/*.zip`・版を上げる前の控え。いずれも、先頭 `_` のフォルダにあり、Git の管理外。
- **守ること**: 外へ持ち出さない・共有しない・Git に入れない。**チャットや資料へ、コマンドラインの値を貼らない**（集計や件数は載せてよい）。

> [!NOTE]
> **理由:** 目的が、読めないプロセスの素性を、コマンドラインで確かめることだから。伏せ字にすると、確かめられなくなる（10-04 に決定）。

## 5. サービスの置き場

共通ルール「常駐サービスの置き場と、exe の置き替え（Windows）」に従う。**このプロジェクトの値**だけを、次に書く。

- **置き場**: 定義は `deploy/rust-ai-pc-memory-collector-winsw.xml`（Git 管理）。exe（本体と winsw の複製）は `deploy/*.exe`（`.gitignore` で除外）、ログは `deploy/logs/`。ビルド出力は `src/pc-memory-collector/target/`。
- **導入**: 一般ユーザーのコマンドプロンプトから `tools\70_deploy\install-pc-memory-collector-service.cmd`。自動で管理者へ昇格する。管理者のコンソールを直接開くと、`T:` や `W:` が見えず、winsw の複製元（`T:/ai-chat-lite/` の winsw）を見失う。
- **導入の最後に表示される「登録された実行ファイル」が、`C:\` で始まっていること**を見る（subst のドライブでないこと）。
